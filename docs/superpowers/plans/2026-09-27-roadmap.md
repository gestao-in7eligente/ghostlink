# GhostLink — Roadmap

Spec: [`docs/superpowers/specs/2026-09-27-ghostlink-design.md`](../specs/2026-09-27-ghostlink-design.md) (§17 defines the milestones).

- **How milestones get planned.** Each milestone gets its own implementation plan, written just before it starts. That way it builds on the code as it actually exists, not on guesses. Plans are executed with `superpowers:subagent-driven-development`.
- **Definition of done.** A milestone is done when:
  - its plan checkboxes are complete;
  - `npm run lint`, `npm run typecheck` and `npm test` pass;
  - CI is green on Windows, Linux and macOS;
  - the work is merged into `main`.

**Cross-milestone rules**

- **Protocol changes stay additive.** New fields and event types are fine. Removing or renaming something requires bumping `PROTOCOL.max`, as described in spec §5.1.
- **DB migrations are append-only:** `002_*.sql`, `003_*.sql`, and so on. Never edit a migration that has already shipped.
- **Every new user-facing string needs both `pt-BR` and `en`.** The typecheck enforces parity.
- **Every new request type needs:**
  - a strict zod schema;
  - a permission check through `permissionsFor`;
  - a rate limit where the spec §13 table gives one;
  - an integration test that covers the forbidden path.
