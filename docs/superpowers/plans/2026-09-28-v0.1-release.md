# GhostLink v0.1 — Release plan (parallel tracks)

Decided with the owner on 2026-09-28: **ship fast**. v0.1 is a public Windows release on GitHub with auto-update.

- Repository: https://github.com/gestao-in7eligente/ghostlink
- Site: https://gestao-in7eligente.github.io/ghostlink/
- Spec: `docs/superpowers/specs/2026-09-27-ghostlink-design.md`. This doc only narrows scope and assigns ownership. Behaviour always follows the spec.

## Scope

**In v0.1**
- Everything from Milestone 1: TLS server, handshake, invites, identity, pinning, onboarding and join, CI, packaging.
- **Text** (spec M2, plus a lite version of M3):
  - channels, messages, history, presence, members, typing;
  - edit, delete, reply, reactions, mentions and unread;
  - safe markdown;
  - roles and permissions with hierarchy, private channels and the cross-reference rules (spec §5.3);
  - invite management, kick, ban and leave, ownership transfer and recovery;
  - server settings UI;
  - desktop notifications for mentions and replies.
- **Voice** (spec M5):
  - LiveKit 1.13.7 for Windows x64 and Linux x64/arm64;
  - dynamic internal ports, the authorized `/rtc*` proxy, tokens with `livekitPermission`;
  - webhooks and reconciliation;
  - join and leave, mute and deafen, speaking indicator, devices, per-user volume;
  - server mute and move;
  - push-to-talk inside the app, plus global push-to-talk on Windows through `uiohook-napi`.
- **Hosting** (spec M7, lite, plus parts of M8):
  - Host mode in the app;
  - own UPnP implementation, address detection, `node_ip` and CGNAT warning, busy-port handling;
  - Windows firewall fix, tray;
  - full CLI and `install.sh` for VPS;
  - identity backup and import (`.ghostkey`);
  - `ghostlink://` deep links.
- **Release** (spec M9, lite):
  - `electron-updater` with Ed25519 verification, release key in a GitHub Environment;
  - `release.yml` for the Windows installer and the server `.tgz`, with checksums and cosign;
  - a lean VitePress site in pt and en: home, download, getting started, hosting (app and VPS), privacy, and the `/j/` invite page;
  - README, SECURITY and CONTRIBUTING.

**UI**: primary color is Discord's blurple (`--accent: #5865f2`, hover `#4752c4`, white text on it), on the near-black dark theme. Never use the old aqua/cyan accent. Use the tokens and don't hard-code colors.

**Deferred to v0.2+**: camera, screen share, files and avatars (M4, M6), macOS build, the full site, load test automation and the outdated-server notice.

## Tracks and ownership

Each track works in its own git worktree, branched from `m1-foundation` after Milestone 1 and the Phase 0 seams have landed. **Only touch files you own.** Anything else goes through the seam interfaces, or through a one-line addition to an index file, which is expected to conflict trivially.

| Track | Server | Shared | Desktop main | Renderer |
|---|---|---|---|---|
| **A Text** | `apps/server/src/text/**` (module `text`), migration `002_text.sql` | `packages/shared/src/chat.ts`, `roles.ts` | `notifications.ts` | `features/{chat,members,server-settings}/**`, `layout/**`, stores `server`, `channels`, `messages`, `members` |
| **B Voice** | `apps/server/src/voice/**` (module `voice`), `livekit/**`, `/rtc*` proxy | `packages/shared/src/voice.ts` | `ptt.ts` | `features/voice/**`, store `voice` |
| **C Hosting** | `apps/server/src/net/**`, CLI, `scripts/install.sh`, migration `003_*.sql` only if needed | `packages/shared/src/host.ts` | `host*.ts`, `deeplink.ts`, `backup.ts` | `features/{host,identity}/**` |
| **D Release** | only the `WEB_SITE_BASE` value | `release.ts` (update public key) | `updater.ts` | `components/UpdateBanner*` |

D also owns `.github/workflows/release.yml`, `docs.yml`, `docs-site/**`, `scripts/{fetch,sign,checksums}*` for release artifacts, and the root docs (README, SECURITY, CONTRIBUTING).

**Seams**
- **Server**: `ServerModule` (see `apps/server/src/MODULES.md`). Modules call each other through `ctx.getModule(name)`.
- **Voice → Text access**:
  - Voice codes against `VoiceAccess { channel(channelId): { type: 'text'|'voice'; userLimit: number } | null; permissions(userId, channelId): number }`.
  - Text exposes an implementation of it on its module.
  - Voice tests use a stub. Integration binds the two.
- **Welcome fields**:
  - Text adds `channels`, `roles`, `members`, `readStates`.
  - Voice adds `voice`.
  - Keys never collide.
- **Permissions**: `packages/shared/src/permissions.ts` from Phase 0. Nobody renumbers the bits.
- **Renderer**:
  - Text owns the main layout and exposes slots (props or a tiny registry) for a voice channel's participant list, the sidebar voice panel and the center voice stage.
  - Voice ships those components.
  - Integration wires them.
- **i18n**: one namespace file per feature, e.g. `i18n/pt-BR/voice.ts` and `i18n/en/voice.ts`, combined in the i18n index. Both languages are always required, and parity is typechecked.
- **Generic server requests from the renderer**: the `server.request(type, payload)` IPC from the desktop seams. The main process refuses `hello` and `auth.proof`.

## Definition of done (per track)

- TDD. `npm run lint`, `npm run typecheck` and `npm test` are green on the track branch.
- Every new request type has:
  - a strict zod schema;
  - a permission check;
  - its rate limit from spec §13;
  - an integration test for the forbidden path.
- Privacy rules from spec §5.3 are covered by tests: audience per recipient, cross-references and `NOT_FOUND` for private channels.
- The track's report lists its public seams and any assumption about another track.

## Integration and release

1. Merge the tracks in order **A → B → C → D**, resolving conflicts in index and i18n files and the layout.
2. Bind `VoiceAccess` and wire the voice UI slots.
3. Full test suite, plus an e2e test with Playwright `_electron` and fake devices:
   - host in app A, join from app B by invite;
   - chat;
   - both join voice and receive remote audio;
   - a private channel stays invisible;
   - kick → no rejoin without a new invite.
4. `npm run dist` → NSIS installer and a smoke test. CI must be green on Windows and Linux (macOS runs tests only).
5. One security-focused whole-branch review, then fix its findings.
6. Merge to `main`, tag `v0.1.0`, `release.yml` publishes the release as normal/latest with a beta label in its notes, the site deploys, and we verify the auto-update path with a `v0.1.1` smoke release.
